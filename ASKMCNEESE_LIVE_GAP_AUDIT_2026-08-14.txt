ASKMCNEESE LIVE GAP AUDIT
Date: August 14, 2026
Audit target: frontend http://127.0.0.1:5173 and backend http://127.0.0.1:8003
Method: Individual live POST /ask calls against the running backend, using exact prompts,
semantic paraphrases, and conversation-history follow-ups. Implementation files and live
Class Planner freshness metadata were also inspected. This was not a mocked test.

EXECUTIVE VERDICT

The system is not broadly trustworthy yet.

Result by area:
  PASS:    1 of 10
  PARTIAL: 6 of 10
  FAIL:    3 of 10

The previous green automated suites prove internal contracts, but they overrepresent exact
phrases already encoded in routing rules. The live paraphrase audit exposes narrow regex
routing, manually curated date-stamped answer records, stale Class Planner availability,
and several severe intent-routing failures.

No production claims should currently say that AskMcNeese understands all offices,
departments, campus procedures, or natural-language schedule requests.

RATING DEFINITIONS

PASS    = exact prompt, ordinary paraphrase, and follow-up all remain correct.
PARTIAL = one exact route works, but a reasonable paraphrase or follow-up fails/drifts.
FAIL    = the main task is unanswered, materially wrong, or routed to an unrelated domain.

WHAT IS ACTUALLY IMPLEMENTED SUCCESSFULLY

1. A real America/Chicago office-hours parser and open/closed/countdown calculator.
   It is trustworthy only when a matching page or curated record contains parseable
   weekly hours.

2. Deterministic source-bound answers for seven curated service records:
   Health Services, advisor lookup, ID cards, international students, parking appeals,
   Registrar, and class-listing conflict guidance.

3. Correct exact-route distinction between Fall 2026 add/drop and withdrawal deadlines,
   including context-preserving follow-up behavior.

4. A real structured course-section datastore and time-overlap computation. It handled
ENGL, proving the computation is not limited to CSCI. The trigger and response shell are
still brittle.

5. Safety boundaries: the assistant does not actually register in Banner and correctly
refuses to approve overrides or perform enrollment.

6. Explicit Class Planner action plumbing and frontend persistence exist. Earlier live UI
verification showed the selected CRNs reaching Class Planner. This audit did not claim
that the underlying staging availability was current.

7. Source provenance exists in the API chunks. For example, the successful ID result
reported source CUR-ID-CARDS, official tier A, structured_specialist retrieval, and the
official URL.

==========================================================================
WHAT IS HARDCODED OR STATIC

1. knowledge/campus_intelligence/service_records.json contains seven manually written
answer records with last_verified = 2026-08-14.

2. knowledge/campus_intelligence/academic_calendar_records.json contains a manually
typed Fall 2026 deadline record with last_verified = 2026-08-14.

3. The compiler uses narrow explicit regex rules for Registrar, Health, lost ID, parking,
I-20, deadlines, advisor identification, and schedule-conflict activation.

4. conversation_context.py explicitly names CSCI, Calculus II, and selected CSCI CRNs.

5. rccs/hybrid.py explicitly writes "selected CSCI choices" and "Tell me which CSCI
CRNs" even when the actual subject is ENGL.

6. Class Planner is running in staging mode from an August 9 dataset with stale seat
availability.

These are useful deterministic safeguards, but they are not evidence of broad semantic
intelligence. The system currently behaves like a hybrid of a real retrieval engine and a
small set of carefully keyed answer cards.

TOP TRUST GAPS TO FIX NEXT

P0 - Prevent catastrophic intent drift.
  A schedule-overlap question must never become a degree plan. A job closing-date
follow-up must never become an academic-calendar request. Conversation domain should be
locked unless the user clearly changes topics.

P0 - Separate verified workflows.
  Advisor lookup navigation is not Banner registration navigation. Do not reuse or imply
one for the other. Add a verified registration workflow or explicitly say it is absent.

P0 - Stop presenting stale schedule availability as current.
  Refresh availability before planning, label stale sections prominently, and avoid
"polished schedule" claims when seat data is nearly five days old.

P1 - Replace narrow synonym regexes with domain/entity normalization.
  Examples that must resolve equivalently: lost/missing/vanished; sick/ill/unwell;
conflict/overlap/clash; parking ticket/citation on windshield; Fall/autumn.

P1 - Generalize schedule conversation state.
  Store target_subject, constraint_course, constraint_crn, and selected_crns as typed
conversation slots. Remove literal CSCI/Calculus II text from memory and answer code.

P1 - Bound and filter course results.
  Default to open undergraduate sections, group by course, paginate, and let the user
change filters. Never dump 108 raw sections in chat.

P1 - Build a governed all-office directory.
  Store office identity, location, contact, timezone, weekly hours, exceptions, source,
and verification timestamp for every campus office. The current Registrar/Health behavior
must not be described as campus-wide.

P2 - Refresh static service records automatically.
  A scheduled verifier should re-read official pages, compare content hashes, invalidate
changed records, and expose the actual verification time in the answer.

P2 - Add paraphrase and conversation-adversarial evaluations.
  Every canonical test must include at least three unseen paraphrases and two follow-ups.
Tests should assert that unrelated specialists are not activated, not merely that one
expected phrase succeeds.

FINAL TRUST DECISION

Safe to demonstrate:
  - Exact Registrar/Health live status with a visible source and regular-hours caveat.
  - Exact ID, parking, advisor, I-20, and Fall 2026 deadline questions while clearly
    labeling the verification date.
  - Class conflict computation as staging/planning assistance, not current registration.

Not safe to claim:
  - General intelligence across all departments and offices.
  - Reliable understanding of ordinary paraphrases.
  - Current seat availability or a truly finalized schedule.
  - Complete Banner registration guidance.
  - Reliable current job inventory.

Overall recommendation: Do not ship the current hardening as "complete." Keep it behind
the beta label, fix the P0 routing/freshness issues, then rerun this same audit with unseen
wording before making trust claims.
