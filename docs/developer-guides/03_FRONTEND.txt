FRONTEND FOLDER DEVELOPER GUIDE
Path: frontend/
Date: 2026-08-16
Project: ACM @ McNeese State University

================================================================================
PURPOSE (WHAT THIS FOLDER DOES)
================================================================================

The frontend is the "face" of AskMcNeese — the website that users see and 
interact with. This is where:
- Users type questions and see answers
- The chat interface displays conversation history
- Class Planner shows course search and schedule building
- About, Updates, and Settings pages live

This is a modern web application built with:
- React 18 (JavaScript library for user interfaces)
- Vite (fast development server and bundler)
- TypeScript (typed JavaScript for better code quality)

================================================================================
WHAT THE FRONTEND DOES
================================================================================

MAIN FEATURES:

1. ASK CHAT INTERFACE (/ask)
   - Type questions in your own words
   - See progressive answers as they stream in
   - View citations and "Learn more" links
   - Conversation history (only sent for follow-ups)
   - Source scope selection (Adaptive, McNeese only, Include web)

2. CLASS PLANNER (/class-planner)
   - Search Fall 2026 courses
   - Filter by subject, days, time
   - Check schedule conflicts
   - Save courses to local schedule
   - View course details (CRN, seats, prereqs, instructor)
   - Accept "add to planner" actions from Ask chat

3. INFORMATION PAGES
   - About (/about) — How AskMcNeese works
   - Updates (/updates) — Change log
   - Status (/status) — System health
   - Settings (/settings) — User preferences

4. ONBOARDING
   - 14-step interactive tour
   - Guest identity (no login required)
   - Feedback form

5. ACM BRIDGE
   - /acm/login — Login to ACM panel
   - /acm/panel — ACM chapter management (separate tool)

HOW TO START THE FRONTEND
================================================================================

FIRST TIME SETUP:

1. Navigate to frontend folder
   cd frontend

2. Install Node.js dependencies
   npm install

3. Create .env file from template
   Copy .env.example to .env
   Set: VITE_API_BASE_URL=http://127.0.0.1:8003

4. Start development server
   npm run dev

The website will be running at: http://127.0.0.1:5173

You should see:
  VITE v5.x.x  ready in xxx ms
  ➜  Local:   http://127.0.0.1:5173/
  ➜  Network: use --host to expose

To test it works:
1. Open browser to http://127.0.0.1:5173
2. You should see "Ask McNeese in your own words"
3. Type a question and click send
4. Answer should stream in (requires backend running on :8003)

HOW A QUESTION GETS SENT (DETAILED)
================================================================================

Let's trace: User types "What calculus courses are offered Fall 2026?" and clicks Send

STEP 1: USER INPUT (ChatInput.tsx)
  - User types in <textarea>
  - Selects source scope (default: "adaptive")
  - Clicks send button or presses Enter
  - ChatInput calls onSendMessage() prop

STEP 2: APP PROCESSES (App.tsx)
  - Receives question text and scope
  - Calls conversationPayloadForAsk(text, messages)
    
    CRITICAL FUNCTION: conversationPayloadForAsk()
    
    This decides whether to send conversation history:
    
    a. Calls shouldUseConversationHistory(question)
       - Returns true if question has:
         · "what about", "how about", "also"
         · Pronouns ("it", "that", "them")
         · CRN numbers
         · Class Planner keywords ("add", "keep")
       - Returns false for complete standalone questions
    
    b. If false (standalone question):
       - Returns: { history: undefined, taskState: undefined }
       - Backend treats as new question, no context
    
    c. If true (follow-up question):
       - Collects last 6 messages
       - Extracts taskState from last assistant message
       - Returns: { history: [...], taskState: {...} }
       - Backend uses context to resolve references

  - Creates new message in conversation history
  - Calls sendQuestion() from useAsk hook

STEP 3: API CALL (useAsk.ts)
  - Constructs POST request to /ask
  - Body: {
      question: "What calculus courses are offered Fall 2026?",
      scope: "adaptive",
      history: undefined,  // standalone question
      taskState: undefined
    }
  - Sends to: VITE_API_BASE_URL/ask (http://127.0.0.1:8003/ask)
  - Uses EventSource for Server-Sent Events (SSE)

STEP 4: BACKEND PROCESSES
  (See 02_BACKEND.txt for details)
  - Backend understands question
  - Searches Class Search database
  - Finds calculus courses
  - Generates answer
  - Streams back via SSE

STEP 5: RECEIVE STREAM (useAsk.ts)
  - Receives SSE events progressively:
    · data: {"type": "activity", "skill": "query_planner", "status": "active"}
    · data: {"type": "activity", "skill": "structured_specialist", "status": "active"}
    · data: {"type": "chunk", "delta": "Here are the calculus courses..."}
    · data: {"type": "chunk", "delta": "MATH 190 Calculus I..."}
    · data: {"type": "complete", "structured": {...}, "citations": [...]}
  
  - Updates state for each chunk
  - Accumulates answer text

STEP 6: DISPLAY (ChatMessage.tsx, ChatAnswer.tsx)
  - Shows activity indicator while searching
  - Displays answer text as it streams in
  - Formats structured course results as cards
  - Shows citations as "Learn more" links
  - Updates conversation history

TOTAL TIME: 2-5 seconds from send to complete answer

================================================================================
CRITICAL: CONVERSATION HISTORY BEHAVIOR
================================================================================

THIS IS EXTREMELY IMPORTANT and was a major bug fix.

RULE: Only send history and taskState for TRUE follow-up questions.

WHY IT MATTERS:
  Before the fix:
    User asks: "What dining meal plans are available?"
    → Gets answer with taskState about dining
    User asks: "What calculus courses are offered Fall 2026?"
    → WRONG: Sent dining taskState to backend
    → Backend tried to answer about dining+calculus (confused)
  
  After the fix:
    User asks: "What dining meal plans are available?"
    → Gets answer with taskState about dining
    User asks: "What calculus courses are offered Fall 2026?"
    → Detects: This is a standalone question (not a follow-up)
    → Sends NO history, NO taskState
    → Backend treats as new question (correct)

HOW TO VERIFY:
  1. Ask question A, get answer
  2. Ask completely unrelated question B
  3. Open browser network tab
  4. Check POST /ask request body
  5. Should see: "history": undefined, "taskState": undefined

WHEN HISTORY IS SENT:
  - "What about biology courses?" (has "what about")
  - "Add that to my schedule" (has "that", refers to previous)
  - "Show me CRN 12345" (has CRN number)
  - "Keep those and add CSCI 150" (Class Planner continuation)

WHEN HISTORY IS NOT SENT:
  - "What calculus courses are offered?" (complete question)
  - "When is the last day to drop?" (new topic)
  - "Where is the library?" (unrelated to previous)

CODE LOCATION:
  - shouldUseConversationHistory() in src/lib/conversationHistory.ts (if exists)
  - conversationPayloadForAsk() in src/App.tsx

SOURCE SCOPE (SEARCH MODES)
================================================================================

Users can choose where to search (ChatInput.tsx):

ADAPTIVE (default)
  - Official McNeese pages
  - Class Search database
  - Indexed knowledge base
  - Curated service records
  - NO open web search
  - Most questions use this

  - Only official campus sources
  - Class Search
  - Indexed content
  - NO live web fetch
  - NO external websites

INCLUDE THE WEB
  - Everything from Adaptive
  - PLUS live web search for context
  - Used for "What is [general topic]?" questions

HOW IT WORKS:
  - User selects from dropdown
  - Sent as "scope" parameter to backend
  - Backend uses appropriate retrieval channels
  - See 02_BACKEND.txt for backend behavior

DEFAULT: Adaptive (set in App.tsx)

CLASS PLANNER FEATURE
================================================================================

WHAT IT DOES:
  - Search Fall 2026 courses
  - Filter by subject, day, time, instructor
  - Check if courses conflict (overlap in meeting times)
  - Build a potential schedule
  - Save schedule locally (browser storage)

DATA:
  - Term: 202660 (Fall 2026)
  - Mode: staging locally (shown in UI)
  - Data from backend /class-planner API
  - NOT real-time Banner data

IMPORTANT LIMITATIONS:
  - Planning only, NOT registration
  - Cannot reserve seats
  - Seat counts may be outdated
  - No student eligibility checking
  - Must register through Banner

KEY COMPONENTS:

ClassPlannerPage.tsx
  - Main page at /class-planner
  - Lazy loaded (not in initial bundle)

CourseSearch.tsx
  - Search bar and filters
  - Calls backend: GET /class-planner/courses?term=202660&query=MATH

CourseCard.tsx
  - Displays: CRN, title, time, instructor, seats, prereqs
  - "Add to schedule" button

ScheduleGrid.tsx
  - Visual weekly grid
  - Shows selected courses
  - Highlights conflicts in red

ConflictChecker.tsx
  - Compares meeting times
  - Detects overlapping sections
  - Calls backend: POST /class-planner/conflict-check

SavedSchedule.tsx
  - Stores schedule in localStorage
  - Key: "askmcneese_saved_schedule"
  - JSON array of course objects
  - Persists across page reloads

ASK TO PLANNER INTEGRATION:
  - When Ask returns structured course results
  - Shows "Add to Planner" button on course cards
  - Clicking saves course to planner
  - Opens planner page

WHAT NOT TO DO (COMMON MISTAKES)
================================================================================

DO NOT:
- Always send conversation history (breaks standalone questions)
- Hardcode backend URL in code (use VITE_API_BASE_URL)
- Commit .env file to Git (contains configuration)
- Commit node_modules/ (installed by npm)
- Commit dist/ (build output, regenerated)
- Restore FAQ suggestion chips on empty screen
- Point at ACM API for Ask questions (separate systems)
- Assume Class Planner data is real-time Banner
- Forget to restart dev server after changing .env
- Make breaking changes without updating tests

COMMON ERRORS:

Error: Cannot connect to backend
→ Check VITE_API_BASE_URL in .env
→ Verify backend is running on that URL
→ Check browser console for CORS errors

Error: History being sent when it shouldn't
→ Check shouldUseConversationHistory() logic
→ Verify conversationPayloadForAsk() is called correctly
→ Add console.log to debug

Error: Styles not updating
→ Hard refresh: Ctrl+Shift+R or Cmd+Shift+R
→ Clear browser cache
→ Check CSS file is imported correctly

Error: Build fails
→ Run type check: npm run typecheck
→ Fix TypeScript errors
→ Check for unused imports
→ Verify all dependencies installed

Error: Tests failing
→ Read test output carefully
→ Check if component structure changed
→ Update test expectations if behavior intentionally changed
→ Run single test to isolate issue
