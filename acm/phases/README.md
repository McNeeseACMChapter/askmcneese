# Build order

## Phase 0 — Governance specification

Before production code: formally decide policy items in [`../policy/`](../policy/).

## Phase 1 — Foundation

Build first:

- Authentication
- Users
- Memberships
- Terms
- Positions
- Role assignments
- Permissions
- Scoped authorization
- Audit log
- Notifications

Nothing else is safe until this layer works.

## Phase 2 — Governance core

- Meetings, agendas, attendance
- Minutes, motions, voting
- Decisions, action items
- Officer appointments
- Document versioning

At this point the system becomes the chapter’s official memory.

## Phase 3 — Execution (projects)

- Project intake / portfolio
- Teams, tasks, milestones
- Risks, issues, change requests
- Deliverables, closure

## Phase 4 — Events

- Proposals, checklists, volunteers
- Registration, attendance
- Documents, post-event reporting

## Phase 5 — Finance and SGA

Only after permissions and audit controls are stable.

## Phase 6 — Communications

Announcements, social calendar, approvals, campaigns, assets.

## Phase 7 — Intelligence and automation

Only after underlying data is trustworthy:

- Extract action items from minutes
- Detect project risks
- Summarize weekly activity
- Warn about missing approvals
- Transition reports
- Volunteer recommendations
- Annual ACM report drafts

AI assists; AI never approves money, grants roles, alters votes, or publishes sensitive content alone.
